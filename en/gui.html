SAP GUI 8.10 uses the Horizon theme: dark blue title bar, white menu bar, system information moved to the right end of the menu bar, thin-line icons. Learn the logon and the five areas first — every transaction afterwards is the same sequence: type the transaction code → Enter → fill the fields → Enter to check → ✓ to save.

1. Logon: three fields decide which system you enter

2. SAP Logon 8.10: choose the system before you log on

The entry point in 8.10 is called SAP Logon, and it is not an SAP screen at all but a connection manager: on the left are your saved connections, and only a double-click (or selecting one and choosing Log On) opens the real logon dialog. The first time you use it you have to create a connection and fill in the system ID, instance number and message server.

3. The theme: what 8.10 looks like, and why your company's screen differs

8.10 defaults to the Horizon theme (the successor to the Quartz family), with Morning and Evening light and dark variants. From 8.10 on there are also custom themes: a company can build a shared theme with the UI Theme Designer, or in the SAP GUI options use Quick Theming to change just 6 main colours, from which every other colour is derived.

Screen elementHow it looks under HorizonDifference from 7.70 / Quartz

A different theme changes no operationEvery screenshot and the simulator on this site are reproduced in Horizon. If your company uses custom colours or the Morning variant, the colours change but the button positions do not — so the rules below about where to type and which key to press hold in any theme.

4. The five areas of the main screen (SAP Easy Access)

5. The command field: the single most important box on the screen

What you typeMeaningWhen to use it
MM03Jump straight there (no /n)The everyday case; starting a second transaction inside the current one stacks the transaction buffer
/nMM03End the current transaction, then start MM03When you are stuck on a screen and want a clean restart
/nEnd the current transaction only, back to the main screenEquivalent to closing the current document (unsaved input is lost)
/oMM03Open MM03 in a new windowWhen you need to compare two screens
/iDelete the current sessionWhen you have too many sessions open
/nexEnd the current transaction and log offSwitching users, or going home
Two traps① The command field takes a transaction code, not a menu path; a wrong entry gives "Transaction code XXX does not exist" and does not damage the document you were typing. ② /n discards unsaved input — do not type /n out of habit halfway through a form; press ✓ to save or F3 to go back instead.
From 8.10 the command field also searchesType *purchase order or part of a menu name and press Enter: the system lists matching transaction codes and menu paths (transaction search). Before you have memorised full T-codes it beats hunting through menus; but mixing a Chinese menu name with an English T-code narrows the results, so for exams and real work nothing beats knowing the T-code.

6. Six toolbar buttons (beginners need only these six)

ButtonNameShortcutWhat it does
✓EnterEnter / F8Runs checks, expands details, confirms dialogs — it does not save
◀BackF3Up one level; asks whether to save if there is unsaved input
💾 (blue)SaveCtrl+SActually writes to the database and issues the document number; only this step creates documents
✕ (red)ExitShift+F3Leaves the transaction, unsaved input is lost
🔍FindCtrl+FSearches a list or table for a keyword
🖨PrintCtrl+PPrints the current document or list
The most common misunderstanding"I pressed Enter, why wasn't it saved?" — Enter only runs checks. In SAP, saving is ✓ or Ctrl+S, and nothing is in the database until the status bar says "... saved / posted".

F1 is the most underrated featurePress F1, then the Technical Information icon, and you see the table the field lives in (MARC, MARD), the field name (WERKS, LGORT) and the parameter ID. Those are exactly the names you need when writing documentation, checking configuration or talking to a consultant.

Message numbers in the status bar (M8083, M7021) are searchable: Help → Application Help → search the message number to see the trigger conditions and the remedy.

9. Personal settings (SU3) and language

  1. Enter transaction SU3 to open Maintain User Profile.SU3
  2. Set parameter ID LANG to ZH / EN / JA: that becomes your default interface language at logon.
  3. Set parameter ID WRK to 1710: many screens then prefill the Plant field with it.
  4. Set parameter ID BUKRS to 1710: the default company code.
  5. Save (✓). It applies at your next logon; in the current session, User → Parameters applies it immediately.
Defaults are not configurationSU3 only changes what you see as a default; it changes no system data. A colleague logging in still sees empty fields, and real documents always use the value actually entered.

Technical information in F1 is the master keyWhen an error says "field XXX not maintained", use F1 → Technical Information to confirm which table and which parameter ID the field belongs to, then check SU3 or SPRO. That single step turns a "mysterious error" into "one configuration item is missing".

11. When a screen "does nothing", check these four things

  • A dialog may be hidden behind the window: SAP confirmation boxes sometimes open off-screen — check the taskbar or press Alt+F6 to bring it back.
  • Required fields are marked with a red underline: SAP marks mandatory fields with a red frame or tick, not an asterisk; leave one empty and you will keep bouncing back.
  • You may have pressed the wrong button: Enter ≠ Save; Back (F3) asks whether to save and choosing No loses everything.
  • Missing authorisation: the message "You are not authorised for XXX" — run SU53 to see which authorisation object is missing, then ask Basis to grant it.
