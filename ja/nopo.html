通常の流れは「先に発注し、後で入庫」です。しかし現場では品物が先に届きます。口頭発注、緊急の補充、仕入先からの先出し。このとき倉庫が「発注がないので受け取れません」と言うだけでは、品物は入り口に積まれたままです。SAP の解方は移動タイプ 101 に購買発注を生成させること——前提として 4 か所のスイッチがすべて開いている必要があり、1 つでも欠けると発注番号の手入力に戻ります。

1. 仕組み：入庫時に供給元を逆引きし、PO を自動で補う

MB01（品目移動）で移動タイプ 101 を選び、品目／プラント／数量／仕入先を入力し、購買発注項目は空欄にします。するとシステムは次の順で供給元を探します：品目マスタの購買ビュー → プラントの供給元リスト → 購買情報レコードの価格。3 つがそろい、かつ 4 つの「自動生成を許可する」スイッチがすべて開いていれば、システムは購買発注を 1 枚生成し、それを使って入庫を転記します。ステータスバーには品目伝票番号と自動生成された購買発注番号が同時に出ます。

MB01入庫 101PO を入力しない→自動PO を生成供給元リスト + 情報レコードによる→品目伝票49xxxxxx 在庫 +→FB03会計伝票在庫 Dr / GR/IR Cr

2. 6 つの前提（1 つ欠けると失敗。この順で設定する）

#どこで設定するか何をするか欠けるとどうなるか
1IMG：購買管理 → 在庫管理 → 入庫 → 購買発注の自動生成（または OMJJ 移動タイプ）101 GR 入庫の 3 番目「購買発注を自動生成」にチェックを入れるMB01 が「購買発注を入力してください」となり、自動生成されません
2IMG：企業構造 → 割当 → 購買 → 標準購買組織のプラントへの割当プラント 1710 に既定の購買組織が必要どの購買組織で作るか分からず、エラーで生成されません
3仕入先マスタ（XK02 / BP）購買データ → 制御データ「購買発注を自動生成」にチェックを入れる「仕入先に自動購買が設定されていません」と表示されます
4IMG：購買管理 → 購買 → 供給元リスト → プラント別供給元リストの要否プラント 1710 の行で「供給元リスト」にチェックを入れるシステムが供給元リストを参照せず、価格も仕入先も決まりません
5ME01（供給元リスト）品目 + プラント に有効な仕入先を保守する（固定供給元も可）「有効な供給元が見つかりません」と表示されます。実テストではここが最も重要です
6MM02 → 購買ビュー「自動購買発注」にチェックを入れるシステムはこの品目を自動生成の対象と見なしません
もう 1 つの暗黙の前提購買情報レコード（ME11）が存在し、価格が正しいことが必要です。これがないと自動生成された PO に正味価格が入らず、入庫金額が 0 になり、会計伝票も金額を記録できません。資料の原文は「以上の設定を終えると、MB01 で 101 入庫を行う際に購買発注を入力しなければ、システムが購買発注を自動生成します」——4 か所のスイッチ + 供給元リスト + 価格、どれ 1 つも欠かせません。

3. 実行：MB01 で入庫、発注番号は入力しない

  1. コマンドフィールドに MB01 と入力して Enter。（8.10 では MIGO でもできますが、「PO 自動生成」の設定は多くの教材が MB01 で見せています。項目が少なく見やすいためです。）MB01
  2. 移動タイプに 101 を入れて Enter。システムが「購買発注に対する入庫」の既定画面を出します。Enter
  3. 伝票日付は今日のまま（または当期日付）にし、購買発注項目は空欄にします。Tab
  4. 品目 R-1002、プラント 1710、保管場所 0002、数量 50、仕入先 100124。F4
  5. Enter でチェック：エラーがなければステータスバーは「チェックが完了しました」だけです。✓ で転記します。Ctrl+S
  6. 2 つの番号を控えます：品目伝票 4900000002、自動生成された購買発注 4500000124（番号はそれまでに作った伝票数に依存します。自分の画面の値に従ってください）。—
  7. ME23N で自動生成された PO を開きます：明細は R-1002 / 50 PC / 180.00 USD、正味金額 9,000.00 USD です。ME23N

4. 会計：自動生成は仕訳を変えず、「根拠があるか」だけを変える

勘定名称借方貸方説明
140100原材料（在庫）9,000.0050 PC × 標準価格 180.00、評価クラス 3000
191100GR/IR 仮勘定9,000.00物は届いて請求書が未着。仮計上の負債を立てる
合計9,000.009,000.00貸借一致

PO の自動生成が解決するのは「伝票がどこから来るか」だけで、記帳の論理は標準の入庫と同じです。在庫が増え、GR/IR が立ちます。MIRO で請求書を受け取って初めて GR/IR が消し込まれ、買掛金に振り替わります。この PO に請求書が来なければ GR/IR は残り続けます——まさに月末の GR/IR 残高一覧（MB5S）で説明を求められるものです。

5. 会計期間：なぜ「先月の荷物が今月受け取れない」のか

入庫は品目帳簿と会計帳簿の両方に書くので、2 つの期間を両方開けておく必要があります。会計期間（OB52）と品目期間（MMRV/MMPV）です。月末に締めた後で新しい期を開け忘れるのが、初心者が最もよくぶつかる壁で、エラーは業務と無関係に見えます。

2 つの期間を開ける順序先に品目期間、次に会計期間（または同時に）開けます。会計だけ開けて品目を開けないと、入庫は「品目期間が開放されていません」になります。逆に品目だけ開けて会計を開けないと「転記期間が開放されていません」になります。両方閉じているときは会計のエラーが先に出るので、品目は問題ないと思い込まないこと。

6. 合格基準とよくあるエラー

  • MB01 で 101、PO を空欄、R-1002 / 1710 / 0002 / 50 / 100124 を入力し、✓ の後にステータスバーへ品目伝票番号と PO 番号が同時に出る。
  • ME23N でこの自動生成 PO を開け、明細の数量と正味価格が正しい（50 PC / 180.00 USD / 9,000.00 USD）。
  • MMBE で R-1002 の 0002 の在庫が 20 から 70 PC に増えている。
  • FB03 で会計伝票を開く：在庫 9,000.00 借方、GR/IR 9,000.00 貸方で貸借が一致する。
  • わざと品目レベルの「自動購買発注」を外してもう一度入庫する：システムは黙って生成せず「購買発注を入力してください」と返すはずです。
  • MMPV で次の期に繰り越した後、今月の日付で入庫する：品目期間のエラーになるはずです。これが月末締めの典型的な症状です。
